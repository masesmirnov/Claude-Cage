# Cage v0.1.7-rc.1

This is Cage's first RC release. Compared with `v0.1.6-alpha-preview`, it focuses on improving multi-system guests, first-run setup, private network device connections, project recovery and file interaction. The `rc.1` in the version number means release candidate, so compatibility issues may still exist. Keep your existing config and virtual disk, and upgrade with the installer or in-app update.

## Tailscale: view and use private network devices after sign-in

- Click "Connect and sign in", complete authorization on the official page, then return to the panel to see your account, network, current Cage address and other devices.
- The device list supports search by name, system or address, with online devices first. Not signed in, waiting for administrator approval, an empty network and connection failure each show a next step.
- Use SSH to reach a device, or create a local connection address in Cage for TCP services such as the web or databases. Apps that support an HTTP proxy can also use device domains, HTTP and HTTPS through the private network proxy.
- SSH public key setup expands only when needed, so joining the private network and remote terminal authentication are not mixed together. If the sign-in page fails to open, a public key error, or a service address fails to create, you can retry directly.
- Disconnecting closes existing private network connections and service mappings, but keeps the device identity and SSH public keys. Private network outer traffic still follows Cage's controlled public exit and pause rules.

This access method uses an embedded node. SSH is configured automatically for transport, and other apps use service connection addresses or an HTTP proxy. Whole-machine transparent VPN, UDP, subnet routing and exit nodes are not enabled. It does not take over the host's Tailscale.

## First use and multi-system environments

- First-run setup selects the guest system, environment storage location and proxy in one place. It supports managed image downloads and creation progress feedback.
- Supports creating macOS, Windows 11 and Linux guests, component provisioning and workbench access. Choose the matching image for a supported host system.
- Cage account settings are synced with the macOS guest account, adding entry points for guest sign-in, password maintenance and permission recovery.
- CPU, memory and other resource settings are managed in one place. They can be edited directly or reset to defaults. The environment and personal config use stable paths.
- System image downloads follow the host's existing proxy, reducing confusion between first-download paths and daily Cage network settings.

## Projects, storage and recovery

- The default workspace is separate from the config folder. It keeps the old environment identity, so an upgrade does not accidentally create a new virtual disk.
- Environment storage migration keeps accounts, config, sign-in state and the persistent virtual disk. Backups from before the migration are kept.
- When external storage is unavailable or migration is incomplete, the workbench offers a recovery entry and blocks accidental startup until recovery. On Windows, the system helper can be repaired before recovery continues.
- For macOS project sharing problems with sign-in, file sharing, screen recording or accessibility permissions, recovery actions are provided, and project connections are checked again after recovery.
- The Windows virtual disk copy, registration and system helper binding flows are also improved, so file attributes or old paths don't prevent the disk from being mounted again.
- The project selection window can remove linked projects and revoke folder sharing. Original files and session history are kept. Before removing, check the usage of terminals, sessions and the editor. The default workspace is kept.

## Daily interaction and cross-device collaboration

- The workbench terminal and remote desktop support `Shift+Enter` for new lines, while Enter still submits. Fixed the loss of the Shift state after focus changes, and kept the order of paste and later keystrokes. The target input box or terminal program must support multi-line input, and input method candidate confirmation is still handled by the input method.
- The session list shows sessions running in other windows and the reason they're in use ahead of time. They become clickable again automatically when they end. When one session is open, other sessions can still be used independently.
- The Desktop window pauses status polling when hidden, and reads again when visible. Multiple viewers share short-lived status results, which reduces duplicate probing and overlapping slow requests.
- In Linux guests, Desktop automatically hides its window after the last viewer leaves, to reduce background drawing. The app and commands keep running. When a computer or phone views it again, the original window is restored.
- Improved request binding, cache ownership and invalidation for text, image and file clipboards. This reduces pasting into an old target or copying old content after switching windows.
- Improved confirmation for downloads, saves and file opening in the browser and the guest desktop. Failures keep a retry entry.
- Improved operation feedback for macOS guest authorization and sign-in windows. The Windows title bar and menus follow the workbench theme.
- Windows background commands run silently, and the local app can still quit when the workbench loses contact. The native message interface on Linux workbenches stays available while the page is open.
- Updated browser settings, workbench, tab and project entry points, and unified pairing transfer and session links between computers and phones.
- Improved presentation of Claude Code multi-account support, session usage limits and account identifiers, and the feature handoff between the remote workbench and native guests.

## Installation, updates and maintenance

- The Windows release installer uses trusted cloud signing. Updates continue to verify the Authenticode trust chain and publisher identity. macOS release artifacts use Developer ID signing and Apple notarization.
- Completed recovery for installation and update failures, including retries. Upgrades and uninstalls manage app files and keep personal user data.
- Improved proxy subscription compatibility, exit region policy, connection recovery, diagnostic redaction, resource detection and concurrent config handling.
- Imported legacy WebSocket subscriptions convert path and header fields, so actual connections use these settings. Exit checks for dual-stack proxy nodes explicitly detect IPv4 addresses.
- Run records verify process identity, so a reused process ID doesn't make an old environment look like it's still running.
- Provides config, diagnostics and native operation entry points for external agents, and verifies downloaded installers.
- Synced the usage docs and download entry, and kept the necessary build source, dependencies and licensing materials. Development plans, research and QA records stay local.

## Supported scope and upgrade notes

- macOS host: Apple Silicon, macOS 14 and later.
- Windows host: Windows 10 22H2 / 11 x64. A Windows 11 guest needs a Windows 11 Pro, Enterprise or Education host that supports Hyper-V.
- Linux host: Debian 12, Ubuntu 22.04 / 24.04 x86_64. Intel Macs, Windows ARM64 and Linux ARM64 hosts are not supported yet.
- Users of the older unsigned Windows preview builds need to download and install this version's trusted signed installer manually, once. After that, signed automatic updates work.
- After adding or updating native guest features, sync the environment components as the workbench prompts. Don't delete `.claude-cage`, old environment disks or migration backups to fix upgrade problems.
- Real account authorization, specific host permissions, audio devices, display scaling, third-party input methods and phone network environments may still differ. Automated, build and isolated network tests do not replace hands-on testing on every device combination.
