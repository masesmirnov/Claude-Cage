# Cage v0.1.8-rc

This is the release candidate of v0.1.8, for users who want to verify it early. It provides installers for Apple Silicon macOS, Windows x64, Linux x64 and Android arm64; the current official release is still v0.1.7.

## Use and upgrade

Before upgrading, save your work, stop the environment and quit Cage, then install the package for your system. You keep your existing account, bookmarks, configuration, projects and persistent disks, with no need to rebuild the environment. When the workbench asks you to update environment tools, you can update them in "Settings → Environment versions".

Windows v0.1.7 users should download the installer from this version's attachments and install it by hand after quitting Cage. This version includes the automatic update fixes; for detailed steps, see the [Windows guide](https://claude-cage.com/docs/windows/).

## Main improvements

- **Browsing and sign-in.** The macOS workbench browses and signs in with Chrome's native window; the Ubuntu workbench uses stable Chromium and keeps existing browser data. Fixed failed Chromium language pack migration.
- **Windows updates and recovery.** Fixed the app folder still being held by processes during updates, and the authentication problem when stopping the environment under trusted sign-in; improved recovery and error messages after a failed update.
- **Claude account restore.** An existing account missing its sign-in credentials can be authorized again, keeping the other accounts and concurrent sign-in data during the restore. Claude Desktop updates keep sign-in data.
- **Picture, scrolling and sound.** Improved touchpad scroll distance in the remote workbench and continuous scrolling under high latency; fixed restoring the activity state shown during capture, and compressed silent audio data.
- **Workbench and connections.** Shows the local time of the environment's time zone and releases finished or canceled proxy connections promptly. Adjusted the management information passed to clients, the clipboard and phone sessions; these adjustments do not guarantee that third parties cannot recognize the runtime environment.

Claude Code and Claude Desktop keep resolving the official latest version for each platform at actual download time, and keep newer versions already installed. If a download or verification fails, you can retry after fixing the network.

## Verification scope

The public attachments should include installers for the three platforms, the matching source archive and `SHA256SUMS`. The final results of signing, notarization, builds and automated tests are defined by this release's record. Full guest creation, real Claude account authorization and model requests, recovery after restart, various Hyper-V hardware configurations, Windows native menus at different display scales, and phone pairing still need acceptance on real machines.

The Android APK requires Android 8.0+, is built from the source matching this version's tag, keeps the v0.1.7 signing certificate, and has update number 4. It passed the signature, non-debug attribute and 16 KiB alignment checks, and was verified in an Android 15 (API 35) emulator for installing over v0.1.7, startup, theme settings and keeping the device key identity. The public APK was downloaded anonymously and its SHA-256 checked; pairing on a real phone still needs acceptance.
