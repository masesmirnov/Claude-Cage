# Cage v0.1.8

This is the official v0.1.8 release. It contains the changes merged into the main line after v0.1.7 and provides installers for macOS, Windows, Linux and Android.

## Main changes

- The clock at the bottom of the workbench can switch between 12- and 24-hour formats in "Settings → General"; it takes effect right after saving and keeps the choice when reopened.
- Lowered the overhead of native environment polling and picture transfer, and improved idle memory reclaim. The Windows browser picture follows the screen pixel density of the viewing device, keeping sharpness and input positions consistent.
- Desktop app updates support resuming and retrying after interruptions, and detect stalls by the time with no data transferred. Windows updates support renewed trusted publisher certificates; Linux offers a releases page link when a new version is found, and is still installed by hand through the system package.
- Android adds update checking, download, verification and system installation in the settings page. When an old APK has no "Check for updates", download the new version from the website and install it over the old one once first.
- Improved macOS physical exit adapter filtering, IPv6 safety checks and browser hardware rendering arguments. Whether graphics acceleration takes effect is still decided by the system, drivers and Chromium.
- Synced the main line's improvements to project and account operations, sign-in callbacks, proxy recovery, the macOS Screen Sharing entry and Windows SSH remote environments.

- Choosing a single-node exit through the Agent CLI now clears the existing multi-hop chain; choosing a node that is already in the chain also completes normally. For multiple hops, keep using the proxy chain settings.
- When installing Linux base packages fails, it shows the failed command, the packages involved and the redacted end of the output, to help tell DNS, connection and package source problems apart. This improvement provides troubleshooting evidence and cannot guarantee automatic recovery from network or package source failures.
- Fixed the answer file being ignored by the installer during manual Windows ISO installation, keeping manual install choices such as the disk and edition.
- Added instructions for when the official Desktop in a Windows guest cannot open shared projects: use shared projects through the terminal, and Desktop can choose a local guest folder; these instructions do not add shared folder support to Desktop.

## Installation and updates

The macOS installer targets Apple Silicon, the Windows installer targets x64, Linux gets an x86_64 DEB and Android gets an arm64 APK. The experimental Intel Mac source and CI builds are merged, but the current public installers do not include Intel Mac releases.

Before installing over the desktop app by hand, save your work, stop the environment and quit Cage. When using in-app updates on macOS or Windows, save your work and click the update button; after verification passes, the app stops the environment, installs and restarts automatically. Accounts, configuration, projects, sign-in credentials and persistent disks are kept. Windows v0.1.7 users must first upgrade by hand once with the full installer as described in the [maintenance guide](https://github.com/Lee-xeo/Claude-Cage/blob/main/docs/guide/maintenance.md). Android installs over the existing version with the same signing identity; iOS keeps the local Xcode build method.

## Verification scope

The feature changes in this version passed macOS, Windows and Linux CI. The signing, macOS notarization, digest and public download verification results of the release packages are recorded in the [matching GitHub Release](https://github.com/Lee-xeo/Claude-Cage/releases/tag/v0.1.8). Locally, the combined code passed full Go and race tests, frontend unit tests and build, real Chromium picture and density tests, clock interaction, the isolated CLI, macOS update rollback, and data retention tests for install, reinstall and uninstall.

This release did not complete real-machine acceptance of all native interfaces. Hosted CI, container and emulator results do not mean that real Windows Hyper-V, Linux KVM, Intel Mac guests, physical Android devices, or Claude authorization and model requests have been accepted.
