# Cage 0.1.0-alpha.1

This is Cage's first version for the internal beta team. It supports Apple Silicon Macs and macOS 14 or later. It puts Linux terminals, browsers and file editors in one desktop workspace, and Cage's own managed proxy handles networking.

## Installation and getting started

Download `Cage-0.1.0-alpha.1-macos-arm64.dmg` from [this version's Release](https://github.com/Lee-xeo/Claude-Cage/releases/tag/v0.1.0-alpha.1), drag Cage into Applications, then open it from the Applications folder. Configure your own Clash / Mihomo YAML or subscription, select a node, then start the environment. The first start downloads the Linux image and developer tools.

You need to prepare your own proxy service and Claude account or authorization. Open a demo or test project, type `claude` in the terminal, and complete authorization for your own account in the Cage browser. For full steps, see [Getting started](../getting-started.md).

For future releases, you can check, download, verify, install and restart from within the app. Downloads go through the selected managed proxy, with no fallback to a direct host connection. New packages must be signed by the same Apple publisher and pass verification. If tasks are running, save and confirm stopping them first. Replacing the app keeps projects, proxy config and the virtual disk.

## Features in this version

- Workspace with a project and terminal list, browser tabs, bookmarks and download management.
- Supports Mac shortcuts, Chinese input and text clipboard. When the window is hidden, browser screen transfer stops, and pages and tasks are kept.
- Network and isolation checks control internet access allowance. A manual pause is saved persistently, and subscription refresh or background restart does not lift it automatically.
- The editor can be restored separately. Download save failures keep retry information, and files with the same name are not overwritten.
- The control service manages background processes by version and program identity. Environment settings show component and tool versions.
- The homepage and README share product content in 15 languages, Chinese by default, switchable from a dropdown.

## Release verification

The app and DMG for this version are both signed with Developer ID, notarized by Apple, have the ticket stapled, and pass Gatekeeper verification. The final control program started with an empty separate config and confirmed version `0.1.0-alpha.1`. The real built-in browser opened the Claude new chat page, and the native window displayed correctly.

Source verification covers Go regression tests, related race checks and vet, frontend lint and unit tests, browser and file operations, the updater, third-party patches and dependency licenses. The installer and matching Mihomo source ship with `SHA256SUMS`. The public release workflow downloads the attachments and verifies the digest, signature, notarization and app version again.

## Internal beta scope and limitations

Use a test project with a backup first. Changes and deletions in shared folders affect the Mac directly. Projects in the same environment share accounts, tools and the file system.

The following still need real-world testing: a full image download and install on a brand-new physical Mac, real-device compatibility with macOS 14, real Claude authorization and model requests, and the full native automatic replacement chain between two signed official versions, including system install authorization, restart and rollback. Unit tests and notarization results do not replace these tests.

The network check reflects the config and sampled evidence at the time. It cannot guarantee that an account won't face platform restrictions.
